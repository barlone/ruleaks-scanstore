# scanstore — REST API хранилища сканов

Хранилище сканов документов водителей. Заменяет прототип `D:\PyProjs\DocScanSort\docstoreapi.py` (FastAPI) с тем же API.
Картинки (JPEG) лежат на файловой системе в папке `store`, метаинформация хранится в PostgreSQL (`jsonb`), настройки берутся из `config.ini`.

## Запуск

1. Подготовьте базу в PostgreSQL (таблицы сервер создаст сам при `migrate = true`):

   ```sql
   CREATE ROLE scanstore LOGIN PASSWORD '...';
   CREATE DATABASE scanstore OWNER scanstore;
   ```

2. Скопируйте `config.example.ini` в `config.ini`, укажите `api_token` (сгенерировать его можно командой `scanstore -gen-token`) и параметры `[database]`.
3. Соберите и запустите сервер:

   ```
   go build -o scanstore.exe .
   scanstore.exe                       # читает config.ini из текущей папки
   scanstore.exe -config D:\path\to\config.ini
   ```

Остановка — Ctrl+C: сервер дожидается завершения текущих запросов (не дольше 30 с). Если при старте БД недоступна, сервер не запускается.

## API

Все методы, кроме `/health`, требуют заголовок `Authorization: Bearer <api_token>`. Ошибки возвращаются в формате FastAPI: `{"detail": "..."}`.

| Метод | Ответ |
|---|---|
| `POST /scans` — multipart: `file` (JPEG), `meta` (JSON-объект с полем `type`, обязателен), `docgroup` (необязательно, см. ниже) | `201`, заголовок `Location: /scans/{id}`, тело `{id, docgroup, sha256, size_bytes, width, height, created_at}` |
| `GET /scans/{id}` | картинка `image/jpeg`; поддерживаются `Range`, `If-None-Match` (ETag — sha256) и `If-Modified-Since` |
| `GET /groups/{docgroup}[?sha256=yes][&metainfo=yes]` | `{docgroup, count, scans: [...]}` — метаданные всех сканов группы в порядке загрузки; каждый элемент — `{id, doctype, docnum, person_name, person_bday, size_bytes, width, height}`, то есть без `file`, `docgroup` (он на верхнем уровне), `created_at`, `sha256` и `metainfo`. `sha256` добавляется при `?sha256=yes`, `metainfo` (в нём OCR-текст, это самая тяжёлая часть) — при `?metainfo=yes`; параметры независимы и сочетаются. Для обоих `no` или отсутствие параметра означает «не включать», другие значения — `422`. Полные данные скана отдаёт `/scans/{id}/meta`. Значение `no` или отсутствие параметра — без `metainfo`, другие значения — `422`. Картинки забираются по `id` через `GET /scans/{id}`. `404` — группы нет, `422` — номер не целое число больше нуля |
| `GET /scans/{id}/meta` | `{id, file, docgroup, doctype, docnum, person_name, person_bday, sha256, size_bytes, width, height, created_at, metainfo}` |
| `GET /health` | `200 {"status":"ok"}`, если БД недоступна — `503` |

Коды ошибок: `401` — нет токена или токен неверный; `404` — скан не найден; `413` — превышен лимит размера; `415` — запрос не multipart; `422` — некорректный JPEG, `meta` или `id`.

### Группы сканов (`docgroup`)

`docgroup` объединяет сканы одной папки: у них одинаковое целое число, по нему в БД есть индекс `scans_docgroup_idx` (`SELECT ... FROM scans WHERE docgroup = 42`). Номер выдаёт сервер из последовательности `scans_docgroup_seq`:

1. Первый скан папки загружается без поля `docgroup`, сервер создаёт для него новую группу и возвращает её номер в ответе.
2. Остальные сканы той же папки загружаются с полем `docgroup=<этот номер>` и попадают в ту же группу.

Скан без `docgroup` всегда получает новую группу, то есть отдельный скан — это группа из одного элемента. Пустое значение поля считается отсутствующим. Все сканы группы одним запросом отдаёт `GET /groups/{docgroup}`. Номер группы, которой ещё нет (выдуманный или с опечаткой), при загрузке отклоняется с `422`, чтобы скан случайно не попал в чужую группу; значение не число или меньше 1 — тоже `422`. Загрузку первого скана папки нужно закончить до загрузки остальных: параллельно можно грузить разные папки, но не файлы одной, пока номер группы неизвестен.

```
curl -H "Authorization: Bearer $TOKEN" -F "file=@scan107_p2__passport.jpg" -F "meta=<scan107_p2__passport.json" http://127.0.0.1:8000/scans
curl -H "Authorization: Bearer $TOKEN" -F "docgroup=1" -F "file=@scan107_p1__snils.jpg" -F "meta=<scan107_p1__snils.json" http://127.0.0.1:8000/scans
curl -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8000/scans/<id>/meta
curl -H "Authorization: Bearer $TOKEN" -o scan.jpg http://127.0.0.1:8000/scans/<id>
```

## Как хранятся данные

- `id` — uuid7, его выдаёт сервер. Скан неизменяем: перезаписи и удаления нет.
- Картинка лежит в `store/<ГГГГ>/<ММ>/<uuid>.jpg`. Год и месяц (UTC) берутся из метки времени внутри uuid7. Путь вычисляется при загрузке и записывается в `scans.file` (относительно `[store].dir`, разделитель `/`); читается файл уже по значению из БД.
- Колонки `scans` заполняются из `meta`: `doctype` — поле `type` (обязательно, иначе `422`); `docnum` — номер без пробелов, тире и скобок, буквы и регистр сохраняются (`passport`/`passport_other`: `fields.series`+`fields.number`; `snils`: `snils`; `inn`: `inn`; `driverlic`/`driverlic_back`: `number`; `drivercard`: `card_number`; у других типов `NULL`); `person_name` — значение `folder_person` в верхнем регистре, а если его нет, то `surname name patronymic` из `fields` в верхнем регистре; `person_bday` — только `fields.birth_date` (`дд.мм.гггг` или `гггг-мм-дд`), других источников нет. Для типа `passport_other` `person_name` и `person_bday` не заполняются.
- В `metainfo` остаётся весь остальной JSON, кроме ключей верхнего уровня `driver_kind`, `source_file`, `page` и `date` (они не сохраняются). Вынесенные значения из него убираются, только если при этом ничего не теряется: `type`, `birth_date`, поля номера, в которых очистка ничего не убрала (без пробелов, тире и скобок), и фамилия/имя/отчество, если они уже были в верхнем регистре и имя взято не из `folder_person`. Поля вроде `snils: "072-261-638 47"`, `folder_person` и `fields.surname: "Егоров"` остаются как есть, а значения, которые не удалось разобрать, остаются на месте.
- Картинка записывается атомарно (`store/tmp/*.part` → fsync → rename) **до** вставки строки в таблицу `scans`. Скан считается существующим только тогда, когда есть строка в таблице. Если вставка не удалась, файл удаляется. Брошенные `.part` старше часа удаляются при старте.
- Файл принимается, только если он целиком декодируется как JPEG. Хранится как получен, без перекодирования.
- `metainfo` хранится в `jsonb`, поэтому порядок ключей при чтении может отличаться от исходного. Значения и большие числа сохраняются без изменений. Символ `\u0000` jsonb не поддерживает, такой запрос получает ответ `422`.

## Отличия от прототипа

- Раскладка файлов `ГГГГ/ММ` вместо `ab/cd` по первым символам uuid. У uuid7 первые символы — это время, и каталог `ab/cd` менялся лишь раз в ~50 дней.
- Метаданные хранятся в PostgreSQL, а не в `<uuid>.json` рядом с картинкой; в ответе `/meta` вместо поля `meta` — колонки документа и `metainfo`, а `meta` при загрузке стал обязательным.
- Ограничение на число пикселей (`max_image_mpix`) и на число одновременных декодирований JPEG — защита от «JPEG-бомб».
- `/health` проверяет доступность БД.
- Для `GET /scans/{id}` добавлены ETag, Range и обработка условных запросов.

## Массовая загрузка

`cmd/bulkload` обходит папку рекурсивно и отправляет каждую пару `<имя>.jpg` + `<имя>.json` через `POST /scans` (JSON уходит в поле `meta`). Картинки сохраняются в файловом хранилище сервера, строки — в БД.

```
$env:SCANSTORE_TOKEN = "<api_token из config.ini>"
go run ./cmd/bulkload -dry-run                                  # только посчитать пары
go run ./cmd/bulkload -limit 20 -workers 2                      # пробная загрузка
go run ./cmd/bulkload -dir D:\PyProjs\DocScanSort\Output -url http://127.0.0.1:8000 -workers 4
```

Файлы одной папки получают общий `docgroup`: первый файл папки уходит без него, остальные — с номером из ответа. Одну папку обрабатывает один поток, параллельно идут разные папки; при продолжении прерванной загрузки новые файлы уже начатой папки добавляются в её группу по журналу.

Сервер должен быть запущен. Ключи: `-dir` (по умолчанию `D:\PyProjs\DocScanSort\Output`), `-url`, `-token`, `-workers`, `-limit` (максимум файлов), `-dirs` (максимум папок целиком, например `-dirs 20`), `-out`. Каждый успешно загруженный файл записывается в журнал `bulkload.jsonl` (`{"img": "<путь от -dir>", "id": "<uuid>", "docgroup": <номер>}`), и повторный запуск такие файлы пропускает. Сервер дубли не отсекает: если журнал потерян, повторная загрузка создаст вторую копию каждого скана. Файлы, на которые сервер ответил ошибкой (например, `422`), в журнал не попадают и пробуются при следующем запуске. Код возврата `1`, если хоть один файл не загрузился.

## Тесты

```
go test ./...
```

Тесты HTTP-слоя используют хранилище метаданных в памяти. Проверка всех реальных сканов без БД (встроенный сервер, файлы пишутся во временную папку): `$env:SCANSTORE_REAL_OUTPUT = "D:\PyProjs\DocScanSort\Output"; go test ./cmd/bulkload -run RealOutput -v`.

Тест PostgreSQL запускается только при заданной переменной `SCANSTORE_TEST_DSN`:

```
$env:SCANSTORE_TEST_DSN = "postgres://scanstore:...@localhost:5432/scanstore_test?sslmode=disable"
go test ./internal/metastore -v
```
